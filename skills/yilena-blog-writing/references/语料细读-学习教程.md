# 学习教程与技术对比：21 篇细读证据

本文只依据 C025—C045 的博客正文归纳，未加载项目既有写作指南。逐篇记录见 `../_meta/annotations-02.json`；C 编号对应总语料清单。以下行号为原始 Markdown 文件的 1-based 行号，复制到包中的原文可按清单核对。

## 阅读范围与边界

21 篇自然语言正文均按原顺序通读，包含全部章节、代码前后说明、表格、引用与结尾；长文按行分块，遇到输出截断后补读了缺失区间。代码围栏内部的重复实现未逐行审计，主要检查它们在解释中的位置、类型和前后衔接。本组未联网核验技术正确性，未逐张打开远程配图，不能据此宣称 API、性能量级或图内信息已经验证。

这组共有 17 篇“知识教程”、3 篇“技术对比”、1 篇“深度机制教程”。这是本组的人工功能分类，不是全库比例。`style_weight: 1` 表示正常风格样本权重，不是文章质量评分，也不代表技术事实可信度。

## 1. 核心声音：和同学一起把原理拆开

作者经常把读者称为“同学”，用“我们”推进一个实际推理过程，也允许自己直接做出工程选择。C042:55 用“像我一样水平还不是很高的同学”起笔；C026:215 预判“有同学可能会搞混通道和线程”；C031:500 说“可能有同学还没听懂，让我们引入一个案例”。这是平行的陪学关系，而不是每段都宣告专业权威。

可转化的写作动作：

- 给出术语后，立刻把它译成执行时会发生什么。C040:373 将控制反转解释为“谁控制对象的依赖创建”发生了反转。
- 当概念容易混淆时，代读者问出具体疑问，再解释差异。不要为了活泼而给每个小节硬塞问句。
- 接近工程决策处，允许用“更推荐”“不建议”“还需要注意”，并写出代价或触发条件。
- 口语不仅出现在开头。C027:632 的“其实也就一句话”和 C043:1596 的“就按顺序读呗”发生在复杂机制解释中，作用是压低理解门槛。

常见承接词包括“也就是说”“其实”“不过”“因此”“所以”“那”“先”“然后”。它们承担复述、反转、因果、时序的功能；复现的是功能，不能按词表机械插入。

## 2. 两种正文节奏，不能平均成一种

**提纲式陪学**占本组多数：中文编号小标题，短段解释、列表和表格相邻；一个局部通常完成“定义 → 机制/流程 → 为什么 → 风险/场景”。C027、C030—C044 都可见这种组织，但不能把它变成每节必须填写的表单。例如 C034 介绍 MyBatis 事务时直接转交 Spring 管理并结束，C027 选型处只用一句话。

**连贯机制论述**在 C028 Gin 与 C029 Go/Java 对比中突出：用连续长段展开工程瓶颈和内部机制，再以代码、对照表或比喻打断。C028:22 交代定位、读者和学习收益；C029:26 用上万个长连接的场景起笔。C029 还使用水流、沟渠、工厂、卡车等连续比喻，末尾带哲学性总结与反问。

不能把这组简单分成“2025短段、2026长段”：C033 LangChain4j 与 C036 PostgreSQL 都发布于 2026 年，仍保持提纲式。应先按体裁、目标读者和选中的原文路由，再参考日期；不能断言存在某次确定的文风转型，更不能据文字推断创作工具或作者身份。

## 3. 教程的结构并非只有“是什么、为什么、怎么做”

### 机制递进

C026 的 BIO 改良仍有局限（179），由此引出 NIO；NIO 的问题再引出 AIO。C040 先写手工 new 的耦合，再引出 IoC（336—353）；静态代理的维护成本又引出动态代理（1089—1101）。段落之间存在前一个方案留下的问题，而不是随机排列的术语。

复用时先确定一个真正需要解释的瓶颈，再带出新机制。不要为了“升级叙事”把旧方案故意写成完全不可用。

### 请求/消息的一生

C032、C037、C039 统一按“组件 → 发送 → 存储/路由 → 消费 → 确认/位点 → 优劣 → 场景”推进，便于同系列横向对照。C045 以一次 HTTP 请求串联 URL、DNS、协议栈、设备转发和服务器响应（249—523）。C041 先给请求链粗图（336），解释各组件后，再按真实调用顺序复盘（1544）。

写这类文章时选择一个可追踪对象：一条消息、一次请求、一个事务。每一步交代参与者、输入、动作、留下的状态和下一步。

### 同维度技术比较

C025 先给选型，再按 16 个问题逐项横比；C036 从 MySQL/PostgreSQL 的共同任务引题（112—142），用已有 MySQL 知识做锚点；C029 则把相同的超时/取消场景分别写成 Go 与 Java 代码（310），之后再谈团队与生态约束（457—477）。

选型文需把横轴固定为同一问题，不能一边列优点、一边只写缺点；历史语料中出现的绝对优劣排序不作为新文事实。

### 短专题用法

C042 只聚焦 `@Transactional` 的扩展参数和自调用失效，不补写完整 Spring 入门。C027 的容量选型部分甚至直接收束为一句话（632）。主题边界小，结构也应缩短。

## 4. 素材策略：展示执行过程，再给工程判断

本组的主要材料是代码、消息/请求流程图、对照表格、容量算例，以及作者自己其他博客的互文链接。C030 “线程八锁”先给代码题再给输出与原因；C035 通过 Alice/Bob/Carol 的时序和表格演算快照；C027:608—612 在大段批处理代码之后，用两段文字重新讲一遍请求如何合并、批次如何回写和清理。

可复用的图文/代码配合是：先解释为什么需要这个例子 → 代码或图表 → 指出关键动作及限制。代码不应当孤立充当篇幅。这里对图表位置的结论来自 Markdown 引用，图内内容需看视觉抽样记录，不能以链接存在替代图片已查看。

系列链接有明确教学作用：C031 将 JMM/并发细节交给 JUC，C043 把 IO 模型交给另一篇文章；作者会说“这里不再做赘述”，为读者提供返回路径。新文若没有对应文章，就不能凭空制造“我之前讲过”。

## 5. 认知框架：可用于组织判断，不能继承旧事实

1. **机制要能回到工程后果。** 数据结构不仅是定义，还要说明为什么影响 IO、空间、锁竞争、可靠性或维护成本。C027 本地缓存最终落到批量网络请求、容量和一致性；C040 IoC/代理最终落到耦合和修改成本。
2. **选择本质上是资源或约束之间的交换。** C035:372 明写索引是空间换时间；C039:300—302 把零拷贝实现解释为业务功能与吞吐量的权衡；C029:457—477 将组织技能与运维能力也加入取舍。不能据此给每个问题强凑“三角形”模型。
3. **已知技术是学习新技术的脚手架。** C036 用 MySQL 理解 PostgreSQL，C033 用 Java 接口/注解/动态代理理解 LLM 服务。新题材优先找读者熟悉的执行模型，并明确类比的边界。
4. **“会用”之后要回答为什么失效。** C028 的 Abort 不终止当前函数（454）、Recovery 不覆盖新 goroutine（534），C040 的三级缓存限制（869—882），C044 的资源耗尽风险，共同说明作者偏好故障边界，而非只展示 happy path。
5. **抽象必须减少实际重复工作。** C034:494—498 在便利后质疑职责混合；C028 将 HTTP 依赖限制在 handler 层。作者关心框架如何让代码易懂、可维护，而不只是在概念上先进。

这些是风格推断，不能把它们包装成作者稳定不变的个人信仰。C025、C032、C044 同时存在强硬、绝对的技术判断，与后期长文的审慎措辞并存。未来写作可以保留明确判断的力度，但应把版本、负载、假设和证据说清楚。

## 6. 结尾和排版：保留选择，排除迁移噪声

本组多数原文有 CSDN“码文不易，留个赞再走吧”赞语，也有作者/原文链接。它是旧平台收尾习惯，不必自动成为新博客固定模板。教程有的以对照表或最后一个知识点自然结束（C030、C034、C043），有的总结适用范围（C032、C037、C039），有的补充未来方向（C041、C044），C029 甚至以回环反问结束。故不能规定“所有文章禁止总结”或“每篇都必须升华”。

中文编号、分级标题、加粗关键名词、警示式引用框、技术名词保留英文都是可选的稳定呈现手段。手工目录锚点、空标题、正文主语缺失、表格粘连、超多空行、“一键获取完整项目代码 java 运行”等明显转存痕迹不应复制；它们不能被美化为故意的文风设计。字体、主题色和代码高亮来自站点渲染，本组仅根据 Markdown 不能归因于作者审美。
