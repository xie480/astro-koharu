# 平台与交付

## 通用调用

给任意能读本地文件的 AI 加载 `SKILL.md`，保留整个目录结构即可。只传入口文件的文字、却不让目标 AI 访问 references 和 raw，不能视为完整加载。

如果目标模型不能访问文件，传入完整 `SKILL.md`、五份蒸馏产物以及所选五篇原文的内容；路径本身不会传递知识。不要要求它凭一段摘要复刻。

可用请求：

> 使用 $yilena-blog-writing，写一篇面向已有 Java 基础读者的性能方案复盘。事实和约束如下：……。请按我提供的数据展开，不补造实测结果，约 2500 字，不含代码。

> 使用 $yilena-blog-writing，按深度解析模式写……。先解释概念边界，再展开执行机制与取舍；技术资料见……。

> 使用 $yilena-blog-writing，根据下列时间线写一篇个人随笔。只使用我给的经历，不替我编造感受：……。

## 安装和迁移

本次交付的是完整目录与 ZIP，尚未写入全局 Skill 目录。将 `yilena-blog-writing` 文件夹放到目标 AI 支持的 Skill 目录，例如 Codex 的用户技能目录或项目 `.agents/skills/`。安装后仍保留 references、raw、_meta 和 scripts，不能只复制 `SKILL.md`。

其他 AI 没有 Skill 自动发现机制时，显式让它读入口，再按入口读取资源即可。本包不调用写作 API，也没有模型或插件依赖；辅助脚本使用 Python 3 标准库。只有重新计算可选词性表时需要 jieba 0.42.1。

## 落盘到 astro-koharu

这部分是当前仓库平台适配，不是从文风蒸馏出来的审美规则。写入前重新检查仓库的内容 schema 和类别配置，避免以后升级造成字段漂移。

- 文件放在 `src/content/blog/`，使用 Markdown。
- 每篇新建文章都必须填写非空的顶层 `link`。先确定最终文件路径，再按 `scripts/koharu/utils/migration-operations.ts` 的当前规则以及 `site.enableSlugTransliteration` 配置生成；规则基于内容路径，不是文章标题。用户明确指定稳定链接时保留用户值。
- `title`、`date` 也是基本字段；按需求添加 `description`、`tags`、`categories`、`cover`、`draft`。
- 交付前运行 `pnpm koharu migrate --check`，确认新文章没有出现在待迁移列表中。该检查扫描整个仓库；如果它指出其他文章缺少迁移字段，只修本次文章，不擅自运行会修改其他文章的全仓迁移。
- `date` 使用用户给定日期及平台时区约定。个人叙事里的事件日期与文章发布日期分开处理。
- 新稿用于审核时可设 `draft: true`；是否发布由当前用户请求决定，调用写作 Skill 本身不意味着发布授权。
- `description` 是页面元数据，单独提炼，不仿旧迁移稿的第三人称摘要去写全文。
- frontmatter 里的标题已由页面渲染时，正文不要再重复一个同名 H1。
- 图片只使用当前项目实际存在或用户给定的素材路径；不要借用 raw 中与新文章无关的图片。
- 编辑其他平台的稿件时，不强塞 Astro frontmatter、站点字段或旧 CSDN 尾注。

本文没有要求运行或修改站点，也不把过时的构建环境观察写成 Skill 的长期依赖。
