# 视觉风格指南

## 观察边界

本指南来自 59 份 Markdown 快照及 5 篇文章全部 11 张正文图片的实际查看。C057/C058 正文相同且均无正文图片；图文计数的 59 篇与 58 篇口径一致。没有把 frontmatter 的 `cover` 当成正文配图，也没有从当前站点主题反推作者的字体或配色偏好。

全语料可确认：220 次正文图片引用，43 篇有正文图片，16 篇没有；含 23 个 Mermaid 围栏，18 篇含表格标记。原始引用计数不等于不同图片数量，也不代表所有远程图片均可访问。以下功能分类只适用于实际打开的样本。

## 排版是解释结构的外显

全语料的 Markdown 呈现差异很大，不能套一种排版密度。

- 提纲式教程：`##`/`###`/`####`、问题标题、项目符号和加粗定义较多，代码和对照表用于查阅。
- 工程方案：按“需求、分析、初版、优化、实现”推进，常出现流程图、SQL、Java、Lua 等块；图代码与文字的距离由当前步骤决定。
- 深度解析：连续机制段落较长，章节标题承担概念分层，Mermaid 和选型表压缩复杂关系。不能把每句因果都改成独立 bullet。
- 直接排障：允许很短，现象、日志、最小改动和补充条件足够，不应为凑篇幅增加架构史。
- 项目记录：演示图、GIF 与按模块展开的代码比重较高。仅需技术细节时，不复制旧文的整套截图展台。
- 随笔：C052 主要依靠时间节点、短段和独句，没有正文图；这是单篇观察，不能规定所有个人文章都不用图。

去重口径下，脚本识别的加粗片段为 1266 次，约每千正文字符 3.57 次；标题文本平均 10.77 字符。加粗计数不包括标题和表格中的强调，分母排除了代码和表格，因此只用于描述语料，不作为新文硬指标。完整口径见 [语言DNA.md](语言DNA.md)。

## 色彩、字级和强调

Markdown 能支持的结论是：作者大量使用标题、加粗、代码、引用、表格和图片；无法从文件本身获得正文的实际字号、行高或深浅主题偏好。

已查看截图既有深色 IDE，也有浅色管理界面；C023 流程图使用浅绿节点、浅黄判断框和黑线，C050 主要是白底黑线并带红字注释，C059 用红框突出参数。这说明颜色服务于图中的功能定位，不能据此制定统一品牌色。

生成时沿用目标平台已有样式。普通正文不额外插入彩色 HTML；强调落在决定、错误关键词、条件或一句关键解释上，避免每段整句加粗。图的字须可读、箭头须有方向；不要求每隔固定段数配图。

## 不复制的视觉残留

原文中的手工目录、超量空行、空标题、损坏的链接标签、平台推广尾注和重复表情属于迁移或发布痕迹。保留其“方便检索、步骤可见、偶尔有情绪”的功能，去掉失效外壳。不要把未实际查看的图片类型、截图中的性能数字或当前网页 CSS 写成已核实的作者视觉规则。
