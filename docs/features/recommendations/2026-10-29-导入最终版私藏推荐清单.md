# 导入最终版私藏推荐清单

## 1. 背景与目标

用户提供了最终版 Excel 清单，并要求按该版本将私藏推荐插入 `/recommendations` 页面。项目的推荐数据由 `src/data/recommendations.json` 静态维护，无需新增接口或存储服务。

## 2. 数据现状与映射

原始清单导入 87 条：小说 37 条、番剧 29 条、游戏 21 条。随后用户在更新后的 Excel 中新增 6 个开源项目，当前总计 93 条。标题、作者、描述、作品链接、个人评分和标签按项目数据模型映射；空描述和空链接保持缺省。Excel 中带有说明前缀的相关链接只提取实际 HTTP(S) 地址。全部条目的 `addedAt` 统一为 `2026-10-29`。

导入条目设为非示例数据，以隐藏原有用于预览的虚构示例提示。用户要求跨分类随机排列，因此将全部 93 条打乱并写入唯一的 `order` 值，默认排列不按分类或原表顺序分组。

## 3. 封面处理

番剧与游戏共使用 50 个封面直链。后续复核时发现四张原图无法在浏览器解码，已替换为可加载来源：兰斯系列采用 [AliceSoft 官方 Blog 的 Rance 10 包装图](https://blog.alicesoft.com/archives/4880741.html)；在魔王城说晚安采用 [Bilibili 番剧图片](https://www.bilibili.com/bangumi/media/md28229876/)；青春猪头少年采用 [Shikimori 番剧海报](https://shikimori.one/animes/z37450-seishun-buta-yarou-wa-bunny-girl-senpai-no-yume-wo-minai)；电锯人采用 [Norma Editorial 发布的动画海报](https://www.normaeditorial.com/noticia/el-anime-de-chainsaw-man-se-estrenara-en-octubre)。用户反馈小说不需要封面，因此小说条目均移除了 `image` 字段，卡片改为纯文字排版。先前生成的小说通用 SVG 现已删除，页面不再为小说预留封面区域。

本轮新增的 6 个开源项目不使用封面。Excel 将 GitHub 地址填写在封面列，因相关链接列为空，导入时将这些 GitHub 地址映射为项目 `url`，不写入 `image`。项目标签按各仓库的说明和 GitHub topics 整理；卡片组件同步调整为开源项目采用纯文字布局。

## 4. 风险与影响

- 番剧与游戏封面仍依赖外部图片站点，来源变更或热链限制可能导致图片加载失败；卡片现有错误回退会显示分类标记。
- 93 条收录日期统一为用户指定的 `2026-10-29`；最近收录排序下日期相同，再按随机后的推荐顺序稳定排列。
- 当前清单含小说、番剧、游戏和开源项目，原有示例数据已被替换；其他内置分类能力保留，但没有条目。

## 5. 验证与结果

写入前通过电子表格读取确认分类数量、标题、图片字段和链接格式；本轮确认新增 6 个开源项目，转换过程检查 93 个唯一 ID、分类计数及 URL 安全协议。静态 JSON 生成成功，GitHub 地址被映射为项目链接，开源项目未设置封面。未运行项目测试套件。

## 7. 卡片与筛选改版

- 卡片改为自然高度的 CSS 多栏瀑布流，不再拉齐同一行高度；小说使用文字排版，番剧使用横向封面，游戏使用侧置封面，并以分类色区分媒介。宽屏为 3 栏、平板为 2 栏、窄屏为 1 栏。
- 按反馈为开源项目增加专属绿色强调色和 `</>` 代码标记。卡片从仓库链接生成 `git clone` 命令，放入终端风格代码块，并提供复制按钮与无障碍状态反馈；开源项目继续不显示封面。
- 鼠标移动时卡片轻微倾斜并移动顶边强调条；触摸设备不依赖 hover，系统启用减少动态效果时取消位移。
- 原生排序下拉改成 Radix 单选菜单；标签筛选从当前清单汇总标签，支持输入搜索、复选多选和清除。选择标签后面板保持打开，点击外部或按 Escape 关闭；重复 `tag` 查询参数保留分享与浏览器历史状态，多个标签按“命中任一”匹配。
- 视觉方向采用现有 Koharu 粉色语义色，搭配新闻/媒体类简洁网格与分类强调色，避免引入新 UI 依赖。

### 默认随机排列（2026-10-29）

- 排列方式默认值改为“随机打乱”，每次打开页面时在客户端生成一次 Fisher–Yates 排列。随机序号保存在页面内存中，分类、搜索和标签筛选沿用同一轮顺序，不会随着每次筛选操作再次洗牌；从浏览器缓存返回页面时会重新生成。
- 随机是默认模式，URL 不保存随机序号，也不写入固定 `sort` 参数，因此重新访问会产生新排列。显式选择“推荐顺序”“评分从高到低”或“最近收录”仍通过 URL 保留。
- 为保证 React SSR 首次输出和 hydration 顺序一致，服务器阶段继续使用确定性顺序；客户端挂载后才切换到本次访问的随机排列。浏览器可能在 hydration 后完成一次顺序更新。
- 更新了排序模型和现有测试中的旧默认值断言；按要求未运行测试套件。定向 Biome 与实际页面交互检查结果记录在本节后续验证项中。
