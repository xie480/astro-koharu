# 歌单页嵌入网易云音乐歌单

## 1. 目标

将用户提供的三个网易云音乐歌单嵌入 `/music` 页面，沿用项目现有播放器和播放列表交互，不替换全局背景音乐配置，也不改播放器 UI。

## 2. 实现方式

`src/pages/music.md` 使用 `{% media audio %}` 媒体块。三个歌单作为三个可切换的播放列表组，由现有 `AudioPlayer` 客户端组件渲染。

歌单名称与 ID：

| 歌单 | ID |
| --- | --- |
| ヰ世界情緒（异世界情绪） | `7991458296` |
| 美波 美波 美波！！！ | `2964644014` |
| DAZBEE | `9841149241` |

Meting 客户端 `parseMusicUrl()` 从网易云 URL 中提取歌单 ID，再请求配置的 Meting API。`uct2` 查询参数保留在页面源数据中，但当前解析器只向 Meting 服务传递 `server`、`type` 和 `id`；播放数据由 Meting 服务按公开歌单 ID 获取。

## 3. 风险和边界

- 播放器加载与播放依赖外部 Meting API、网易云歌曲权限和浏览器网络环境。
- Meting API 返回歌单曲目不代表每首曲目都可播放；版权、地区或会员限制可能导致个别歌曲播放失败。
- 歌单页只配置这三个播放列表，不改变 `config/site.yaml` 中的全局 BGM 播放器数据。

## 4. 验证

通过项目配置的 Meting API 逐一请求三个歌单，HTTP 均返回 200；返回曲目数分别为 269、27、137。播放列表名称通过网易云歌单详情接口确认。页面源数据解析校验确认有 3 个歌单组，ID 和 `uct2` 参数均保留。

`pnpm check` 通过，Astro 报告 0 个错误、0 个警告和 2 个既有 `document.execCommand` 弃用提示。直接执行 `tsx scripts/koharu.tsx migrate --check` 通过：扫描 58 篇文章，0 篇需要迁移。

构建和浏览器验证受当前执行环境阻断：仓库 `pnpm build` 包装命令返回 `[ERROR] fetch failed`；直接执行 Astro 构建时，在配置加载阶段报 `module is not defined`，位置为 `node_modules/.pnpm/extend@3.0.2/.../extend/index.js:68`，Node 24 下复现。开发服务器未能就绪，因此浏览器中的实际播放器交互暂未验证；`agent-browser` 也无法访问 `C:\Users\Xie\.agent-browser` socket 目录（权限拒绝）。这些问题尚未证明由本次歌单内容改动引起。
