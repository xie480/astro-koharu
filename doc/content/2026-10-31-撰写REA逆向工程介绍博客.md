# 撰写 REA 逆向工程介绍博客

## 1. 背景与目标

根据需求撰写并扩充《GitHub 爆火的 REA 是什么？从工作原理到实战，带你搞懂 AI 如何逆向工程软件》，说明 REA 的定位、分析链路、安装方式和适用边界，配用户指定人物封面、网络检索的 Ghidra 界面截图和本地流程示意图。

## 2. 资料核查与关键判断

- 2026-10-31 查阅官方 GitHub 页面时，仓库显示约 412.6k stars。文章将其约写为 41.2 万并注明统计日期，避免把随时间变化的数据写成常量。
- 官方资料把 REA 描述为 Agent 与逆向分析工具之间的工作流/接口层；它可通过 MCP 接入 Agent，也提供 CLI。分析结果包含证据及限制条件。
- 官方仓库支持通过 MCP 接入支持本地 MCP Server 的 Agent；CLI 示例输出模块、导入关系、Electron 边界及相应证据。文章补充说明大型应用完整 Evidence 可能非常大，需注意结果范围和存储方式。
- 官方资料明确说明：静态 JavaScript 分析不需要原生分析引擎；原生二进制的伪代码、汇编、符号、调用及引用通常需要配置 Hopper、Ghidra、IDA 或 Kuna 等 Provider。
- JavaScript/Electron、网站/浏览器、.NET、Android APK 等功能与依赖按官方 README 和 JavaScript 分析指南核对；文章区分静态分析、动态观察和不同目标格式的前置条件。
- 官方公开案例记录了 REA 4.1.0 对 Windows Calculator 11.2508.4.0（x64）的百分号逻辑分析。文章保留案例版本，并明确说明这是对官方展示的复述，不是本机复现。
- MCP 被描述为 AI 应用和工具服务之间的通信协议；不把 MCP 等同于 Agent 推理或反编译引擎。
- 文章区分反编译伪代码与原始源码，避免声称 REA 能完整还原软件工程项目。
