# 修复大肥鱼文章迁移检查失败

## 1. 现象与影响

静态构建执行 `pnpm build` 时，在 `pnpm koharu migrate --check` 阶段退出，尚未进入 `astro build`。部署日志显示唯一被拦截的已提交文章是《如何养一条最近很火的大肥鱼？》，迁移动作为“补充 link”。

## 2. 根因

仓库构建脚本要求所有文章先完成旧字段迁移。迁移器会为没有 `link` 或旧 `slug` 的文章按内容文件路径生成稳定链接；本篇最初缺少 `link`，因此检查失败。配置文件校验通过与该迁移错误无关。

## 3. 修复与取舍

- 根据当前迁移规则和文件名，给文章补充 `link: '如何养一条最近很火的大肥鱼'`。
- 后续检查还发现 REA 文章缺少 `link`，按同一规则依据它的最终文件名补齐。
- 没有运行会批量改写所有文章的迁移命令，只修改这两篇文章，避免影响其他草稿。

## 4. 验证结果

- `tsx scripts/koharu.tsx migrate --check` 在两篇文章补齐后通过。
- Frontmatter 检查确认两篇文章的 `link` 均与迁移器按文件名计算的结果一致；大肥鱼文章的 `draft` 仍为 `false`，三张正文截图路径均存在。
- 未运行完整 Astro 构建；原部署日志中的失败发生在 `astro build` 之前。
