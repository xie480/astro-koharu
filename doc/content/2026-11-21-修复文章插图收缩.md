# 修复文章插图收缩

## 背景与目标

部分文章使用没有显式 `width`/`height` 的 SVG 插图。线上页面中，这些图片会缩小到约 300px 或更窄，无法利用正文列宽。本次修改的目标是让文章插图默认占满正文宽度，同时保留竖图并排布局的收缩规则。

## 现状与根因

全局 `src/styles/global/reset.css` 将 `figure` 设置为 `inline-size: fit-content`。Markdown 图片会由 `rehypeImagePlaceholder` 包装成 `figure.markdown-image-wrapper`，但原来的文章图片样式没有覆盖这个尺寸。

对于只声明 `viewBox` 的 SVG，浏览器按替换元素默认尺寸计算包装器宽度，导致图片和 `figure` 一起收缩。线上页面读取到首张插图的 `figureWidth: 300px`、`imageWidth: 300px`，与问题截图的表现一致。

## 方案与修改

在 `src/styles/theme/markdown.css` 的 `.prose .markdown-image-wrapper` 中增加 `width: 100%`，覆盖 `reset.css` 的收缩规则。已有的 `.portrait` 规则位于后方，仍会将竖图包装器恢复为 `fit-content`，因此不会改变竖图分组的布局策略。

## 验证结果

- 新增 `src/lib/markdown/image-layout.test.ts`，验证普通图片包装器声明 `width: 100%`，并验证竖图仍声明 `width: fit-content`。
- 运行 `node --test --test-isolation=none src/lib/markdown/image-layout.test.ts`：1 个测试通过。
- 运行 Biome 针对本次修改文件的检查：通过。
- 已检查线上文章 DOM：修复前的 SVG 包装器宽度为 300px，确认了根因。

## 未验证范围与风险

本地 Astro 开发服务器、`astro check` 和生产构建均未能启动，环境在加载现有 Astro 配置时因依赖 CJS 模块出现 `module is not defined`。全仓库 Biome 检查还存在 `docs/design/readme-showcase/scenes.mjs` 的既有格式提示及 `.impeccable` 缓存格式提示，未对这些无关文件做修改。

CSS 修改只影响文章 Markdown 图片包装器；竖图的专用覆盖规则保持不变。
