# 修复“大肥鱼”文章图片预览

## 背景与现象

文章在 Codex 的 Markdown 文件预览中只显示插件截图的替代文字。截图文件实际存在于仓库中；`draft` 状态与图片加载无关。

## 根因

正文原先引用 `/img/posts/...`。这是网站根路径：Astro 会把 `public/` 文件按站点根路径提供，但 Codex 的文件预览没有挂载 Astro 的 `public/`，因此请求落在预览器自身的根路径下，找不到图片。

## 修改

- 将三张插件截图放入 `src/content/blog/assets/`。
- 正文改用相对文章文件的 `./assets/...` 路径。Astro 的 Markdown 支持相对引用 `src/` 中的本地图片。
- 封面继续使用 `/img/posts/deepseek-big-fat-fish.png`，它是站点公开资源地址。
- 文章 frontmatter 的 `draft` 设为 `false`。

## 验证与限制

- 单篇 `lint-md` 检查通过。
- 本地检查确认 `draft: false`，且三条正文图片引用都能解析到实际文件。
- 全仓 `lint-md` 有 189 条既有错误，均报告其他文章中的 `no-multiple-space-blockquote`；本次文章单篇检查通过。
- 未执行 Astro 构建或浏览器页面验证，因此没有把站点端渲染描述为已验证。
