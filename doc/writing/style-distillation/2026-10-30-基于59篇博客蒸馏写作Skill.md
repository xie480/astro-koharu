# 基于 59 篇博客蒸馏可复用写作 Skill

## 背景与边界

用户要求从本项目的 59 篇博客归纳真实的语言、行文、文章结构等特征，交付可供后续 AI 生成博客的完整 Skill 包。用户明确要求本次无视项目既有文风指令，因此不读取、不复用根目录 `agent.md` 与 `docs/writing/文风.md`，也不让通用去 AI 味规则覆盖语料本身。

2026-10-30 检查时，当前仓库为 `astro-koharu`，分支 `main`，HEAD `4b50b74`。工作区已有用户改动（包括写作规范和一篇新稿），本次全部保留。Git 跟踪的博客正好 59 篇，目录实际有 60 篇；未跟踪新稿不纳入本轮，以免改变用户指定语料范围。

## 分析设计

- 使用 `writing-dna-skill` 的六层方法与 `skill-creator` 的包结构和验证方法。
- 冻结 59 篇原文快照并记录 SHA-256、源文件和日期，使包离开项目后仍能读取原文校准语感。
- 将文章分成三组通读非代码正文，审阅代码块的作用与分布；用逐篇标注保留开头、结构、结尾、素材与证据位置。
- 独立统计正文、代码、标题、段落、句长、标点和图文标记，避免代码与 frontmatter 摘要污染语言结论。
- 检查两份 JDK25 近重复稿：原文均保留，统计同时给出 59 篇原始口径与 58 篇去重口径。
- 按体裁与时期区分写法，不将唯一一篇个人随笔泛化为技术博客默认口吻。
- 交付位置为 `skills/yilena-blog-writing/`，另提供可迁移压缩包；本次不安装到用户全局 Skill 目录，不改变站点功能。

## 已知方法限制

仅有 Markdown 不能推出真实页面字号、颜色与图片作者身份。图片内容需另行抽样查看；没有看到的图片不作内容判断。

当前 Python 环境最初没有 `jieba`，pip 尝试未获得可用发行包；随后从 PyPI 获取 0.42.1 源码，在忽略缓存中解包并实际完成词性统计。最终同时保留 jieba 自动分词表和固定词表子串计数，明确区分两种口径。自动词性存在技术语境歧义，没有冒充人工语言学复标；第三方词典与源码不进入交付包。

## 结果与验证

### 确认的主要发现

1. 语料不是单一腔调。教程中有提纲式陪学与连贯机制论述；方案复盘偏“约束→候选→暴露不足→修改”；排障由现象和对照直接进入；深度 AI 长文强调概念边界、系统职责和生产取舍；随笔依靠时间线和预期变化。
2. 体裁优先于年代。2026 年仍有提纲式教程，日期较新的工具文也不等于长段论述；部分原文有追加与迁移迹象，元数据日期不能解释为确定的风格转型时间。
3. 反复出现的组织动作是先明确所需信息、沿数据路径算操作量、让当前约束决定方案、通过职责区分概念、允许更新旧判断。这些是写作倾向推断，不是作者人格或技术正确性认证。
4. frontmatter 摘要、手工目录、空标题、缺词、推广串、CSDN 尾注和重复稿不能与核心文风混合。真实存在的长句、对比纠偏、比喻和总结也不能被通用禁词清单抹掉。

### 实际统计与图片核验

- 59/59 篇逐篇元数据，58 份不同正文；C057/C058 的正文 SHA-256 完全相同，只是 frontmatter 的 link 不同。
- 172 条带原始行号的短引文已由脚本逐条核对。
- 去重口径下，识别正文 352251 个非空白字符，平均句长 32.43 字符；短片段约占 30%，该指标含列表项，不能转成新稿硬配额。具体数字和算法见包内统计与方法文档。
- 59 份原文共 220 次正文图引用，43 篇有正文图；另有 23 个 Mermaid 围栏，18 篇含表格标记。图片计数没有混入 cover，也不等于不同图数量。
- C004/C009/C023/C050/C059 五篇的全部 11 张正文图片已逐张打开。按主要功能分为证据 4、操作演示 2、流程解释 4、情绪 1。小样本不外推为全站占比，不从 Markdown 推断实际页面字体与色系。
- 排障语料中有整段报错写在引用块而非围栏中。统计脚本据此排除 3 行明显日志/SQL，避免它们污染句长；原文证据完整保留。

### 核心交付和决策

`skills/yilena-blog-writing/` 包含入口 `SKILL.md`、UI 元数据、五份核心蒸馏指南、三份细读依据、语料索引、方法边界、成稿检查、平台适配、59 篇 raw、逐篇标注与详细统计，以及选样/统计/验证脚本。整合文档 `Writing-DNA.md` 为 2127 字符，低于方法要求的 4000 字上限。

写作入口要求每篇新文重读五份核心产物与五篇不同正文，按体裁和主题校准；原文中的命令与提示词只是语料，不是执行授权。素材不足时区分方案推演、估算和实测，禁止移植旧文经历、数字、日志和截图。个人随笔与工具介绍各只有一篇直接样本，明确保留弱推断边界。

脚本只承担可重复的选择与统计，不伪装成文章生成器。详细指标按篇拆分，避免单个 JSON 过大影响仓库质量工具。ZIP 保留一个完整 Skill 根目录；不含缓存、第三方 NLP 源码或 Python 编译产物。

### 独立使用测试与改进

另派未继承分析结论的代理，仅加载包与模拟写作请求，离线撰写“内部积分活动导入十万条数据”的约 1200 字方案复盘。给定事实明确无压测、无旧版耗时、不接入 MQ、数据库和框架未定。

代理实际读完五份核心产物与 C001/C002/C018/C023/C053，完成 1289 个非空白字符的成稿。复核可见：没有伪造性能实测；20 万次现有查询是操作数推导，约 200 次是有明确批次与每类查询一次请求条件的示例；未将其说成全部任务往返数，也未强加框架或 MQ。该验证说明本次使用能走通，不是风格相似度盲评或技术方案实测。

试用暴露两个实际问题：粗粒度词匹配会漏掉直接相关的 C001；合并读取长材料时工具可能截断。已补充主题近义词与结构标注检索、输出命中理由、加入该题材回归检查，并在入口要求检查截断和补读。修正后该请求的选样包含 C001，全部 29 组检查通过。索引增加声音列，方便人工校正；选样仍是词法辅助，不声称语义最优。

试写与原始使用记录位于忽略缓存 `.cache/yilena-skill-evaluation/`，不是发布博客或站点功能变更。

## 风险、价值与后续

本次形成的是可追溯、可迁移的写作工具：把“像作者”拆成可选择的体裁与叙述动作，用真实原文约束抽象指南。它降低下次 AI 只凭简短文风描述猜测的需要，但没有量化节省时间或风格还原度。

没有核验全部旧文的技术结论、执行其代码、打开全部远程图片、构建站点或做浏览器 UI 验证；这些不属于本轮写作包验证。原文远程媒体仍可能失效，文本快照可独立使用。没有全局安装、自动发布、Git 提交或推送；原有用户改动保持不动。后续如需覆盖更多个人题材，应增加同类语料，而不是从单篇随笔扩展成全能人格模型。
