# 私藏推荐

访问 `/recommendations`。条目由 `src/data/recommendations.json` 维护。当前有小说、漫画、番剧、游戏、开源项目、其他各一条界面示例，全部设置 `demo: true`，不代表博主的真实推荐、评分或使用感受。

页面复用 Koharu 的双栏布局、首页侧栏、紧凑封面和现有粉色语义 token。支持小说、漫画、番剧、游戏、开源项目和其它自定义分类；分类、搜索、推荐顺序、评分排序与最近收录排序保存在 URL 查询参数中，可分享并通过浏览器前进/后退恢复。

## 添加条目

以下为虚构（fictional）的字段说明示例，不代表博主的真实推荐：

```json
[
  {
    "id": "my-first-pick",
    "title": "虚构作品名称",
    "category": "小说",
    "demo": true,
    "author": "作者（可省略）",
    "description": "自己的推荐理由或感受（可省略）",
    "image": "/img/recommendations/my-first-pick.webp",
    "url": "https://example.com/work",
    "rating": 8.5,
    "addedAt": "2026-10-27",
    "order": 1,
    "tags": ["可选标签"]
  }
]
```

| 字段 | 要求 |
| --- | --- |
| id | 必填，整个列表中唯一且稳定 |
| title | 必填，作品或项目名称 |
| category | 必填，建议使用小说、漫画、番剧、游戏、开源项目、其他；也支持自定义分类 |
| demo | 可选，布尔值；缺省为 false。true 时显示「示例」标记，评分标为「演示评分」 |
| image | 可选，建议用 public 下的本地图片，写成 `/img/...`；也接受 HTTP(S) URL |
| url | 可选，HTTP(S) 外链；无链接时仍可完整展示条目 |
| description、author | 可选，普通文本，不解析 HTML |
| rating | 可选，0～10 数字；0 与「未评分」不同 |
| addedAt | 可选，有效的 YYYY-MM-DD 日期，用于最近收录排序 |
| order | 可选，数字越小越靠前；不填时沿用数组位置 |
| tags | 可选，字符串数组 |

图片、链接、评分和日期均可完全省略。无图片时展示分类标记，图片加载失败也回退到该标记；无评分与无日期的条目在对应排序下放在末尾。字段格式在构建边界校验，错误会包含字段名，避免静默生成危险链接或错误评分。没有自动抓图、外部评分同步或第三方 API 依赖。

## 替换示例

1. 直接编辑对应条目的标题、分类、描述、链接、评分、日期与标签，或者删除示例后添加自己的条目。`id` 在列表中保持唯一。
2. 图片放在 `public/img/recommendations/`，`image` 使用 `/img/recommendations/文件名`。现有四张 SVG 是本地原创分类插画，图片内明确写有「示例封面」，并非作品真实封面。
3. 内容与评分已确认为自己的推荐后，删除 `demo` 字段或设为 `false`，同时替换示例描述和封面。保留 `demo: true` 可以继续预览；页面会明确提示示例身份。真实条目与示例可同时存在。
4. 「其他」类的虚构条目故意没有封面、作者、外链、评分与日期，用于检查可选字段留白时的样式。要恢复无内容页面，将数据设为 `[]`。

演示评分仅用于展示数值与排序效果，没有同步任何外部平台评分。演示日期只是排序预览数据。示例中的外链在本轮核对到以下官方来源：

- 小说：[《小王子》官方网站](https://www.lepetitprince.com/)。
- 漫画：[集英社《SPY×FAMILY》书籍页面](https://www.s-manga.net/items/contents.html?jdcn=08882011882011315501)。
- 番剧：[《葬送的芙莉莲》动画官方网站](https://frieren-anime.jp/)。
- 游戏：`故事游戏示例` 是明确标注的界面占位数据，不代表真实作品或个人评分。
- 开源项目：[Astro 官方仓库](https://github.com/withastro/astro)。

## 参考与取舍

- [NeoDB 官方仓库](https://github.com/neodb-social/neodb)：借鉴跨媒介收藏与个人评分/评论的组织方式。
- [Karakeep 官方仓库](https://github.com/karakeep-app/karakeep)：借鉴链接、笔记、图片等可选内容组成收藏条目，以及列表与搜索的入口。

仅参考产品模式，本模块没有复制两者的代码。个人博客采用静态 JSON 与小型 React 筛选岛，避免引入账户、数据库、爬虫或收藏服务。

## 验证

纯数据测试位于 `model.test.ts`，覆盖可选字段、0 分、无评分排序、无日期排序、分类与关键词组合、稳定排序、数据校验以及 URL 状态往返；同时校验 `demo` 布尔值、普通条目默认非示例和本地封面的文件完整性。测试不固定真实收藏条目的数量，因此替换或删除示例不需要改测试。页面和移动端的实际浏览器检查由本轮整体验收记录。

页面使用 React 的服务端预渲染（`client:load`），服务器返回空态或全部条目内容（含示例身份），不依赖客户端脚本生成正文。关闭 JavaScript 后会显示全部条目并隐藏不可用的筛选控件；查询参数筛选在 hydration 后同步。评分和日期通过固定语言/UTC 的 Intl 格式化，避免服务端与客户端时区不同引起内容不一致。
