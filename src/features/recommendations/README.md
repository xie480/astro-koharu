# 私藏推荐

访问 `/recommendations`。条目由 `src/data/recommendations.json` 维护。当前收录 93 条：小说 37 条、番剧 29 条、游戏 21 条、开源项目 6 条，数据来自用户提供的最终版私藏推荐清单。

页面复用 Koharu 的双栏布局、首页侧栏和粉色语义 token。小说采用纯文字排版；番剧与游戏使用封面并按不同结构呈现。开源项目使用独立代码标记和终端风格克隆命令区，命令从仓库链接生成并可复制。卡片采用自然高度的瀑布流布局。默认排列为“随机打乱”，每次访问页面时重新洗牌；调整分类、搜索或标签时保留本次顺序。评分、最近收录和推荐顺序可手动选择，并随 URL 保存。

## 添加条目

以下为虚构（fictional）的字段说明示例，不代表博主的真实推荐：

```json
[
  {
    "id": "my-first-pick",
    "title": "虚构作品名称",
    "category": "小说",
    "demo": true,
    "author": "作者（可省略）",
    "description": "自己的推荐理由或感受（可省略）",
    "url": "https://example.com/work",
    "rating": 8.5,
    "addedAt": "2026-10-27",
    "order": 1,
    "tags": ["可选标签"]
  }
]
```

| 字段 | 要求 |
| --- | --- |
| id | 必填，整个列表中唯一且稳定 |
| title | 必填，作品或项目名称 |
| category | 必填，建议使用小说、漫画、番剧、游戏、开源项目、其他；也支持自定义分类 |
| demo | 可选，布尔值；缺省为 false。true 时显示「示例」标记，评分标为「演示评分」 |
| image | 可选；小说与开源项目卡片不显示封面；漫画使用竖版封面，番剧使用横版封面，游戏使用侧置封面；图片可使用 public 下的图片（`/img/...`）或 HTTP(S) 图片直链 |
| url | 可选，HTTP(S) 外链；无链接时仍可完整展示条目 |
| description、author | 可选，普通文本，不解析 HTML |
| rating | 可选，0～10 数字；0 与「未评分」不同 |
| addedAt | 可选，有效的 YYYY-MM-DD 日期，用于最近收录排序 |
| order | 可选，数字越小越靠前；不填时沿用数组位置 |
| tags | 可选，字符串数组 |

图片、链接、评分和日期均可完全省略。无图片时展示分类标记，图片加载失败也回退到该标记；无评分与无日期的条目在对应排序下放在末尾。字段格式在构建边界校验，错误会包含字段名，避免静默生成危险链接或错误评分。没有自动抓图、外部评分同步或第三方 API 依赖。

## 维护条目

1. 在 `src/data/recommendations.json` 中维护标题、分类、描述、链接、评分、日期与标签；`id` 在列表中保持唯一。
2. `image` 可以填写 `public/` 下的本地图片路径或 HTTP(S) 图片直链。小说和开源项目不填写 `image`；小说使用纯文字布局，开源项目用仓库链接生成可复制的 Git 克隆命令；漫画、番剧和游戏可使用封面直链，加载失败时显示分类标记。
3. `demo: true` 仅用于界面预览，会显示示例身份；真实条目应省略该字段或设为 `false`。当前清单条目均为非示例数据。
4. `addedAt` 使用有效的 `YYYY-MM-DD` 日期。当前 110 条均收录于 `2026-10-29`；后续条目按实际收录日期填写。没有图片时页面会保留纯文字或分类标记布局。

评分来自用户提供的清单，仅表示个人喜好；未填写的评分和日期保持留白。

## 参考与取舍

- [NeoDB 官方仓库](https://github.com/neodb-social/neodb)：借鉴跨媒介收藏与个人评分/评论的组织方式。
- [Karakeep 官方仓库](https://github.com/karakeep-app/karakeep)：借鉴链接、笔记、图片等可选内容组成收藏条目，以及列表与搜索的入口。

仅参考产品模式，本模块没有复制两者的代码。个人博客采用静态 JSON 与小型 React 筛选岛，避免引入账户、数据库、爬虫或收藏服务。

## 验证

纯数据测试位于 `model.test.ts`，覆盖可选字段、0 分、无评分排序、无日期排序、分类与关键词组合、稳定排序、数据校验以及 URL 状态往返；同时校验 `demo` 布尔值、普通条目默认非示例和本地封面的文件完整性。测试不固定真实收藏条目的数量，因此替换或删除示例不需要改测试。页面、桌面/窄屏布局及筛选交互的实际浏览器检查由本轮整体验收记录。

页面使用 React 的服务端预渲染（`client:load`），服务器返回空态或全部条目内容（含示例身份），不依赖客户端脚本生成正文。关闭 JavaScript 后会显示全部条目并隐藏不可用的筛选控件；查询参数筛选在 hydration 后同步。评分和日期通过固定语言/UTC 的 Intl 格式化，避免服务端与客户端时区不同引起内容不一致。
